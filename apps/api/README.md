# HTTP API

NestJS 11 API under `/api/v1`, built from the same TypeScript workspace as the worker. Public health routes are `/health/live` and `/health/ready`; readiness executes PostgreSQL/schema and Redis checks. `/api/v1/openapi.json` generates OpenAPI 3.1 from the shared Zod wire schemas and actual operation catalog. Explicit constructor injection supports the esbuild server build without inferred decorator metadata.

Development-only `POST /auth/demo` accepts `{email,name?}`, creates/resumes an isolated workspace, seeds five editable agent versions, and issues a random opaque HttpOnly/SameSite strict cookie; only the hash is stored. `NODE_ENV=production` with development auth enabled fails configuration validation. This first slice does not implement a production identity provider; configure a verified production auth integration before exposing it publicly.

Every workspace operation resolves membership from the session and includes workspace ownership in SQL. Foreign tenant IDs return 404. JSON mutation origins are checked against `ALLOWED_ORIGINS`, falling back to `PUBLIC_BASE_URL`; browser traffic uses the same-origin web proxy. Authorization and eligibility are enforced by the API and rechecked by dispatch. Auth/webhook endpoints have bounded per-process IP rate limits (30/200 requests per minute); public ingress must provide a shared limiter for multiple API replicas. Imported files are bounded to 5 MiB, JSON bodies to 7 MiB, lists to 100 rows. List cursors currently represent validated offsets with deterministic created-at/ID or row ordering; event cursors are PostgreSQL bigint ID strings and enforce bigint bounds.

Import upload is JSON `{filename,contentBase64,mapping:{phone,name?,email?,consent?,outcome?},region?,synthetic?}`. Validation runs asynchronously through the transactional outbox. Corrections use `{mapping?,region?,corrections:[{sourceRow,cells:{columnName:value}}]}`; corrections accept existing source rows/columns only, with at most 50 columns per row; a selected campaign freezes its import, so correcting an in-use import requires a new upload. Blocking invalid/formula/phone rows require correction. Duplicates/suppressed/consent-missing rows remain explicitly excluded and do not prevent otherwise valid imports from becoming ready. Suppression persists independently of reimports. Once source-file retention expires, revalidation returns 410 `IMPORT_SOURCE_EXPIRED` and requires a new upload.

Draft campaign creation and `/plan` never perform telephony. Simulation and default plans identify the deterministic local planner and pin an immutable agent version. With `MODEL_PROVIDER=sarvam` and a separate `SARVAM_MODEL_API_KEY`, LIVE plans may use the official sarvamai SDK to propose only bounded steps/questions; simulation remains local even when that key is configured. The model receives no contact rows, identifiers, eligibility, policy or budget authority. Its work runs before a short planning transaction, which rechecks the campaign snapshot and recomputes trusted policy/eligibility/cost. Failed model work returns safe503 `MODEL_UNAVAILABLE` without claiming a model plan exists or launching anything. Plans record actual planner/model provenance. `/simulate` and `/launch` require `{confirmed:true}` plus an `Idempotency-Key` (8–128 letters/digits/hyphens/underscores). Campaign mode must match the action. Live launch also requires complete acknowledged server configuration, explicit consent, authorized nonsynthetic destinations, a fresh reviewed plan, one concurrent call and a reservation estimate inside the configured cap. Plan estimates do not guarantee a provider invoice cap.

Campaign pause/cancel prevents pending dispatch and preserves outcomes from already-active calls. Resume returns actual server state. No Sarvam termination endpoint is claimed. Reports are asynchronous CSV/XLSX exports of terminal campaigns; generation waits until no pending/calling rows remain, including after cancellation. Report requests are idempotent, artifacts are private/authorization checked with retention expiry, and downloads are audited. Business column names and extracted answer keys are preserved by serialization; provider attempt/interaction IDs, upload bytes and artifact bytes are withheld from JSON read models. Authorized call inspection shows only stored transcript/analysis; missing values remain null.

`/campaigns/:id/events` and `/events` replay persisted ordered events after a cursor. `/campaigns/:id/stream` emits default SSE `id`/`data` frames, respects `Last-Event-ID`/`after`, polls bounded database batches, emits heartbeat comments, closes on downstream disconnect, and tells the browser to reconnect on dependency failure. Reconnects reconstruct state from PostgreSQL. Active SSE responses register with an injectable stream manager. `beforeApplicationShutdown` emits a reconnect notice, ends every registered response, and stops its polling loop before Nest closes the HTTP adapter; database and Redis resources close afterward. New streams are refused while shutdown drains. This ordering prevents an open EventSource connection from consuming Docker's 30-second stop grace and requiring SIGKILL.

Sarvam ingress is `/webhooks/sarvam/:token`. The token is compared in constant time, the official payload is schema validated/correlated to an existing attempt, and a normalized durable inbox + reconciliation outbox commit before acknowledgment. The documented terminal attempt identity deduplicates repeated callbacks; contradictory repeats are audited without replacing stored outcomes. The bearer route is a documented application fallback because Sarvam's inspected contract publishes no signature scheme. Keep ingress proxy access logs redacted. No API route itself initiates real calls; only the guarded worker may do so.

Run through root Compose commands. Owner verification: `npx eslint apps/api packages/contracts packages/config` passed; `npx vitest run packages/contracts packages/config apps/api` passed 24 tests at implementation handoff. Root integration evidence supersedes these counts after later changes. Tests cover strict confirmation, terminal/unknown no-redial transitions, timezones/overnight policy, spreadsheet export prefixes including fullwidth forms, production demo rejection, default mock config, generated OpenAPI and private read-model serialization. Live calls were not performed.

Final composed restart verification: `npm run test:integration` passed 28 tests across five files in 83.39 seconds. With an SSE response kept open while a confirmed simulation ran, `docker compose restart api` completed in 358ms. The captured live Docker die event reported exit code143 (SIGTERM), rather than the previous forced SIGKILL code137 after 30,435ms. Four unique terminal mock attempts and replay after the prior cursor remained intact. The dedicated test is `tests/integration/api-restart.test.ts`; its isolated run also passed. Stream cleanup happens before adapter closure, and database/Redis cleanup afterward. No live provider call was made.

Optional SDK post-call summaries apply only to completed connected LIVE conversations with actual transcript and explicit model configuration. `summarySource`, `summaryModel` and `summaryFailureCode` identify SDK output or truthful local fallback; provider-extracted answers are preserved. `/integrations.planner` reports sanitized configuration readiness, not a live provider connectivity probe. The model key is separate from the Voice Agents workspace key. Call initiation remains the verified HTTP adapter because the inspected official SDK exposes no instant outbound telephone operation.
