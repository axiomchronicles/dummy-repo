# Worker

Separate BullMQ process with queues `outreach-imports`, `outreach-dispatch`, `outreach-reconciliation`, `outreach-analysis`, `outreach-reports`; every payload is strict `{id: UUID}`. Jobs have five safe infrastructure attempts, exponential backoff starting at 1s with 0.3 jitter, stable prefixed IDs and bounded concurrency (dispatch4, others2). PostgreSQL guards, not Redis IDs, authorize effects.

Run `npm run dev:worker` or Compose worker. HTTP `/health/live` and `/health/ready` on `WORKER_PORT=3001` distinguish process life from database/schema, Redis and recent successful publisher/recovery heartbeat. SIGTERM stops coordination, closes workers/queues/Redis/Pool. Root Compose grants a shutdown grace period.

A two-second bounded coordinator transaction claims up to50 outbox rows with SKIP LOCKED, enqueues, then marks publication. Another bounded recovery scan rebuilds unfinished DB intents after Redis/worker restart. Published execution intent is recoverable through unfinished imports/reports/analyses/inbox/queued contacts; retained outbox is evidence. Mock interrupted attempts reuse the original UUID/deterministic result. After expected mock latency plus grace, recovery uses an attempt/timebucket job key so a killed process's still-active Redis lock cannot delay network-free completion; database terminal guards remain authoritative. Live dispatching older2 minutes and accepted older30 minutes become unknown; no redial. Delayed callback can reconcile unknown. Terminal results append events, usage and independent analysis intent in one transaction; analysis/report cannot call a provider.

Dispatch locks campaign, contact and workspace and checks current running state, latest explicit consent/suppression, timezone/window, local concurrency/rate and budget reservation. Live calls acquire a transaction advisory lock shared across all tenants/workers: global Sarvam concurrency1 and at most20 starts/minute; unknown ambiguous attempts retain the global slot until callback/operator reconciliation. Workspace/campaign checks also apply; external organisation traffic can still cause vendor rejection. Pause/cancel prevents new claims; active calls may finish. One attempt per campaign contact. Cost is a duration-derived estimate and separate zero simulation usage; no guaranteed invoice cap.

Imports parse quoted CSV through streaming csv-parse, XLSX with ExcelJS under compressed/expanded archive bounds. File≤5MiB, rows≤10,000, columns≤50, cells≤2,000 chars, XLSX central entries≤1,000 and expanded size≤50MiB. Phone parsing uses libphonenumber max metadata and explicit known source region; synthetic files only reserved555-01xx. Formula-like fields require correction; E.164 '+' phone is permitted. Duplicates/suppression/missing consent persist row feedback and are excluded; invalid/formula rows require correction. Reimport links stable contacts and cannot clear suppression or regrant suppressed consent.

Reports asynchronously join persisted contacts/attempts/analysis in stable order, export CSV/XLSX with mode and unknown values and formula-safe exports (CSV quoted tab-prefix per OWASP, XLSX explicit strings plus apostrophe), and persist private bounded bytes/status/row count. Artifact/transcript/analysis expires at configured retention; expired sessions are deleted. Finished source imports/row cells and completed inbox conversation payloads expire after `RETENTION_DAYS`; expired source corrections are unavailable. Contact identity deletion remains operator-managed and suppression stays durable.

Tests: `npm test -- apps/worker/src/worker.test.ts`. Public composed workflow and restart/dedup/tenant checks live under root integration/e2e suites. Audited library docs: https://csv.js.org/parse/options/ (CSV Parse options;7.0.3), https://github.com/exceljs/exceljs/tree/v4.4.0 (ExcelJS4.4.0 README), https://github.com/catamphetamine/libphonenumber-js (README;1.13.15 max metadata), https://docs.bullmq.io/guide/workers and /guide/connections (BullMQ5.81.5; Redis maxRetriesPerRequest null), all accessed2026-10-24.

Live attempts snapshot server configured app ID/version/connection ID in private `provider_config` (no key/caller/token). Local editable persona versions are simulation configurations; changing their prompt does not change the committed Sarvam agent. Operators must configure and test the matching app/version in Sarvam before enabling live. Duration retains fractional seconds; live estimates round actual seconds up to whole60-second pulses, so60.2seconds costs two agent pulses.

A connected live callback with absent duration retains `estimatedCostMinor=null`; no estimated usage entry is fabricated and the prior reservation ledger remains.

Report artifact expiry clears bytes and records `ARTIFACT_EXPIRED` while keeping the completed report job terminal; authorized downloads return410 and regeneration creates a separate report job without repeating calls.

Optional SDK summary uses `sarvamai`1.1.12 only for connected LIVE attempts with stored transcript and MODEL_PROVIDER=sarvam. SIMULATION remains free/local under every model configuration. A timestamp/token claim lease prevents concurrent summary jobs; SDK work runs outside transactions and completion rechecks token/state/expiry. The result changes summary and explicit summary_source/model/failure_code only; provider-extracted answers/transcript stay authoritative. Invalid or unavailable model output preserves truthful local summary and never repeats a telephone call.
