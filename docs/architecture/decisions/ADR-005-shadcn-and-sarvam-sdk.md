# ADR-005: monochrome shadcn workspace and supported Sarvam SDK scope

Accepted2026-10-24 following the explicit current user request. This supersedes ADR003's native-CSS frontend choice. Use Tailwind4.3.3 and authentic official new-york-v4 shadcn registry components with neutral tokens, monochrome actions, open data sections and compact navigation. Upstream component URLs/hashes are tracked in frontend provenance. Public shadcn/Geist/Linear references inform layout; no proprietary implementation or branding is copied.

The published official sarvamai1.1.12 TypeScript SDK covers model APIs. The official sarvam-conv-ai-sdk0.0.42 covers browser microphone/WebSocket conversations. Neither exposes instant outbound PSTN calling. Therefore the verified outbound REST adapter stays behind VoiceProvider. The actual model SDK is used for optional configured LIVE planning content and post-call summaries; all simulation stays local/free even when model credentials are set.

Model output is restricted to conversation steps/questions or a summary. IDs, eligibility, consent, policy, costs, state transitions and launch remain application authority. Request maxRetries0 and bounded timeout/token/JSON limits avoid unintended repeat requests. API captures a planning snapshot before SDK I/O and rechecks it inside a short write transaction. Worker summary I/O occurs outside the transaction, with claim-token/expiry guards. Transcript/extracted fields remain authoritative provider data; model summaries have explicit provenance and safe failure fallback.

This is the least-surprising reversible supported SDK integration under the user's request to follow current docs; it does not invent a phone SDK method. Optional reference/scope questions were offered; work continued with the stated neutral design and supported model scope. No real model or telephone request was used for verification. See docs/research/sarvam-typescript-sdk.md, shadcn-theme.md and ui-reference-audit.md for audited sources.
