# Queues, durable execution and recovery

PostgreSQL transactions persist state + audit/campaign event + outbox. One bounded publisher locks outbox rows SKIP LOCKED, adds stable prefixed UUID jobs (no colon/all-digit IDs), then marks publication. Crash after add may publish twice; every handler rereads and claims database state. Redis dedup is not local/external execution authority.

Job families: imports, dispatch, reconciliation, analysis, reports. Small periodic outbox/recovery/retention tasks run in worker rather than adding a queue for each helper. Payloads contain IDs/version only, parsed by Zod. Bounded exponential backoff with jitter is for safe transient infrastructure failures. Validation/authorization failures persist terminal safe codes. Analysis/report retries never call provider. Actual queue names/payload/retry constants are synchronized from worker implementation.

Dispatch consistently locks campaign before contact, checks running state, latest consent/suppression, calling window/timezone, campaign/workspace in-flight limits and atomic integer budget reservation. A unique attempt per campaign contact is written in dispatching state before provider initiation; transaction ends before bounded HTTP. Paused pending jobs remain pending until resume; cancelled pending work is invalidated. Pending ineligible contacts record exclusion reasons. Active attempts continue receiving outcomes after pause/cancel; no unverified termination promise.

Mock initiation is deterministic/network-free and can safely recover interrupted mock state. Real dispatching/accepted requests interrupted or uncertain become unknown/reconciliation-required, never queued for another dial. Later correlated verified callback may reconcile unknown. No external exactly-once claim. Late contradictory terminal callback is quarantined/audited, not silently applied.

Ingress validates bearer route/schema/correlation, deduplicates provider+attempt terminal callback, and persists normalized redacted inbox + reconciliation outbox atomically before acknowledgement. Processor commits domain result/analysis job/events and inbox processed marker together. ID-less uncertain requests retain local metadata correlation. Sarvam has no documented retry/idempotency/signature/cancel contract at this boundary.

Recovery queries unfinished imports/reports/analysis/pending campaign contacts/inbox and stale published outbox; safely re-enqueues from database intent after Redis/worker restart. Completed/unknown live attempts are never redialed. PostgreSQL/Redis driver reconnect plus readiness reflects dependency outages. Worker shutdown stops pollers/intake, awaits bounded active processors, closes queue/Redis/Pool; Compose grants grace. Persisted event ID strings support ordered bounded SSE replay and no in-memory-only event loss.

## Implemented constants and limits

Queue names are outreach-imports, outreach-dispatch, outreach-reconciliation, outreach-analysis and outreach-reports. Strict payload is {id:UUID}; publication job ID outbox-<UUID>, normal recovery recovery-<UUID>. Jobs use five total safe infrastructure attempts, exponential backoff starting1s with0.3jitter, dispatch concurrency4 and other queue concurrency2. Dispatch database policy further bounds campaign concurrency; liveworkspace concurrency1 and20starts/minute. Coordination runs every2seconds, publisherbatch50, recoverydispatchbatch100 with a rotating UUIDcursor for fairness. PostgreSQL statement15s/lock5s/driver20s timeout; producerRedis commands3s, workerRedis reconnects indefinitely; readinessRedis pingbounded1s.

Killed mock work can safely recover its existing local attempt after expected latency plus grace using a distinct timebucket recovery job; no telephone side effect exists and terminal writes deduplicate. Live dispatching older2minutes or accepted older30minutes becomes unknown, retaining correlation; it never enters automatic dialing again. These are conservative application policies, not documented Sarvam call limits. Reports/imports/analysis retry only their own work. Source/inbox conversation and transcript/report expiry is controlled by RETENTION_DAYS.

Live claims also acquire the shared organisation advisory lock and enforce one global Sarvam attempt in flight and20local starts/minute across workspaces/workers. Unknown attempts continue occupying that slot until verified callback or operator reconciliation; external organisation traffic remains outside this product's view. Report expiry removes bytes and sets an expiry reason without changing the terminal completed lifecycle. Download checks expiry before artifact readiness and returns410; regeneration is independent of calls.

API stream cleanup uses an injectable registry in Nest BeforeApplicationShutdown, ending active SSE responses before the HTTP adapter closes. Actual restart with an open stream completed in358ms via normalSIGTERM143, with four persisted terminal outcomes and intact replay. Worker and API shutdown/restart acceptance is covered by the integration suite. Local rejected initiation records retain a null vendor attempt identifier; required external terminal webhook identifiers remain validated against the official schema.
