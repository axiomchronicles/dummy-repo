# Voice provider boundary

Authoritative audited current HTTP contract: [Sarvam research](../research/sarvam-contract.md), accessed2026-10-24; APIv1. Domain consumes provider-neutral initiate/normalize contracts. Mock default never uses HTTP and returns deterministic connected/no_answer/busy/failed with explicitly synthetic transcript and nullable unknown answers.

Sarvam POST `https://apps.sarvam.ai/api/outbounds/v1/orgs/{org_id}/workspaces/{workspace_id}/outbounds`, header `X-API-Key`, body `app_config:{app_id,app_version,connection_config:{connection_id,agent_phone_number}}`, `user_config:{user_phone_number}`, optional `webhook_config:{url,metadata}`.200 `{attempt_id}` means accepted only.422 has optional validation detail; vendor body never logged. Server configured identifiers only. Optional overrides omitted because committed agent defines voice and language. Exact schemas/fixtures live in provider/contracts packages.

Terminal callback has `attempt_id`, status connected/no_answer/busy/failed, channel_info; nullable duration/interaction_id/failure_reason/final_agent_variables/webhook_config/interaction_transcript. Transcript turns role agent/user and en_text. Missing nullable fields become null. No invented recording URL, billed cost, event ID, timestamp, or objective-success claim. Raw provider failure strings are normalized safe codes. Metadata local attempt ID is correlation, not authorization.

No documented signature/authentication header, create idempotency key, delivery retry or instant-call cancellation was found. Fallback is an explicit acknowledged HTTPS high-entropy secret route, constant-time comparison, proxy token redaction, bounded schema/rate checks and stored attempt correlation. This is bearer protection, not cryptographic provider proof. Adapter/live launch stays disabled unless all server requirements are configured and explicitly acknowledged. No blind POST retry on timeout/reset/5xx/invalid200; ambiguous becomes unknown/manual-review. Read-only analytics reconciliation is optional and remains disabled unless fully implemented/verified.

Live requires provider=sarvam, live switch, workspace key/org/workspace/app/version/connection/caller IDs, HTTPS callback base+random token, fallback acknowledgement, allowlisted authorized test destinations, consent, policy caps and explicit API/UI confirmation. Synthetic contacts are refused live. No startup/seed/tests/manual browser preview uses live. Actual environment names are in config and .env.example and synchronized at integration.

Cost: inspected PAYG ₹3.50/min rounded60sec pulses, separate telephony/GST; configured conservative reservation estimate is not invoice. Provider has no verified max-duration override here, so hard invoice spend cannot be guaranteed; UI must disclose estimate and server kill switch/local attempt-count cap. Default live concurrency1 below documented PAYG organisation4, rate locally<=20/min accounts only this product traffic. No free Sarvam tier promised. Active calls may finish after cancellation.

## Persona and configuration snapshot

The outbound endpoint selects a committed Sarvam app/version; it does not expose a general prompt override. Local editable persona versions organize campaign planning and simulation. A matching Sarvam deployment must be configured before those edits govern real conversation behavior. Each live attempt records the server-selected app/version/connection snapshot privately; browser JSON withholds provider identifiers. Fractional duration is preserved before estimating documented 60-second billing pulses.
