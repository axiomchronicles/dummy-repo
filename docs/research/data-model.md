## Driver and migration decision

Choose `pg.Pool` with `drizzle-orm/node-postgres`. It serves ordinary local PostgreSQL, supports explicit checked-out transaction clients, and introduces no cloud dependency. No pg-native or prepared-statement optimization needed for this workload. `postgres.js` also officially works but adds no needed capability; no driver benchmark is used as a requirement.

Keep `packages/database/src/schema.ts`, `drizzle.config.ts` and `packages/database/migrations/**`. Explicit `drizzle-kit generate --config ...` produces reviewed SQL; explicit one-shot `migrate` applies it with database schema-history checks; idempotent development seed follows. API/worker readiness requires schema presence. Never invoke schema push or seed destructive resets from serving startup. Application transactions use `db.transaction`; raw SQL helpers use one checked-out client with guaranteed rollback/release.

## Proposed relational model

IDs are UUIDs except monotonically ordered event cursors, which are BIGINT. Times are `timestamptz` in UTC; browser serializes ISO 8601. Never use a JavaScript number for an unbounded BIGINT cursor. Every tenant row carries workspace ID; repositories require workspace identity and include it in queries. Composite `(workspace_id,id)` foreign keys on sensitive tenant relationships prevent cross-tenant edges even when application code is wrong. Auth user/session is global; membership selects authorized workspace.

State, tenant, identifiers, phone identity, foreign keys, money, correlation, timestamps and ordering are relational columns. Data that needs indexed selection is not hidden exclusively in JSON.

## Storage and retention

First slice caps imports at 5 MiB, 10,000 rows and 50 columns. Store bounded row data for correction and parse in bounded batches; spreadsheet inherently needs an explicit whole-file memory ceiling. Keep exported artifacts in PostgreSQL `bytea` with an output byte limit and expiry: authorization-checked API download streams bytes, private caching, sanitized filename. This avoids object storage as unneeded infrastructure while artifacts are small. Large recordings or unrestricted files must use private object storage with random keys/short-lived authorized links in a later scope; do not store recording media in PostgreSQL.

Phone normalization is E.164 only when provided international prefix or known source region; never guess India from a UI locale. Synthetic contacts use reserved fictional North American 555-01xx ranges and `synthetic=true`; dispatcher refuses synthetic in live mode. Persist suppression by stable workspace/normalized-phone identity so deleting contacts/reimport cannot erase opt-out. Retain the minimal suppression digest after contact PII deletion, with documented keyed hashing if implemented. No blanket cascading delete from contacts to suppressions.

Reports and transcripts/analysis have configurable short retention (recommended 30 days) and periodic actual deletion; audit/outcome metadata may remain longer under workspace policy. Do not claim retention automation if not implemented. Avoid soft delete on every table: archive campaigns/agents/contacts where history is required; immutable versions and operational evidence remain; raw import rows and artifacts may be purged at expiry. General logs never contain phone/session/raw transcript/provider payload.

## Transactions, queues and indexes

- Campaign launch: lock campaign row FOR UPDATE, check source status and confirmation/policy, ensure unique idempotency key, transition campaign and eligible contacts, append audit/event and insert dispatch outbox in one transaction. Repeated same key returns existing launch; a different key cannot launch active/completed state.
- Dispatch: lock campaign row before contact/attempt in consistent order; recheck pause/cancel, consent/suppression, calling window, cap/concurrency, reservation; claim one unique attempt and mark dialing before external side effect. Release transaction before HTTP; provider response/callback reconciliation is a new short transaction. Crash while dialing becomes unknown, never queued again automatically.
- Outbox publisher claims a bounded batch with FOR UPDATE SKIP LOCKED and a lease; enqueues stable IDs; only marks publication after successful queue add. Crash between add/mark republishes safely, so processors require database idempotency. Redis loss requires replay of published-but-domain-unfinished outbox, not merely unpublished rows.
- Callback ingress validates route/body/correlation, inserts unique terminal inbox and business outbox transactionally, then acknowledges. Repeated insert conflicts succeed without duplicate effects. Processor locks attempt; a completed result is never rewritten silently.
- Analysis/report jobs are idempotent against their own state and never call telephony. Immutable completed attempts are reused when regenerating reports.
- Recommended B-tree indexes: campaigns `(workspaceId,createdAt,id)` and `(workspaceId,status,id)`; imports/reports/agents same stable list ordering; campaignContacts `(campaignId,status,position)`; attempts `(workspaceId,campaignId,createdAt,id)` and partial active state index; outbox partial `(availableAt,id) WHERE publishedAt IS NULL`; inbox partial `(receivedAt,id) WHERE processedAt IS NULL`; sessions tokenHash/expiry; suppressions `(workspaceId,normalizedPhone)`; campaign/attempt events `(campaignId,id)` / `(callAttemptId,id)`; reports workspace/requestKey; usage attempt/kind.
- Paginate list queries with capped limits; event cursors use `id > cursor ORDER BY id`. Report aggregation is one joined/batched query, not one request/query per contact. Monetary values are integer minor units; estimates clearly separate from verified invoices. Never silently include simulation in live usage.

## Acceptance and integration interface

Database package should export `db`, `pool`, schema named tables, `transaction`, `appendCampaignEvent`, `appendAudit`, `enqueueOutbox`, migration/seed scripts and a small `withWorkspace` repository boundary where useful. Keep transaction helper types inferred from Drizzle rather than broad `any`. Lead/API/worker must agree exact fields before implementation.

Required checks: empty-DB migration and repeated migration safe; seed creates exactly five editable personas without calls; unique/cross-tenant/check/FK violations fail; rollback does not leave domain event/outbox; duplicate launch/webhook causes one attempt/result; worker restart does not redial persisted dialing/unknown; suppression survives reimport; CSV/XLSX rows match query state; bounded artifact expires/deletes when retention task claims to exist.

## Implementation reconciliation

Actual schema exports 22 tables and four versioned migrations. Tenant composite UNIQUE table constraints replace index-only uniqueness because selected stable Kit generates foreign keys before indexes; clean migration proves the order. Call duration preserves fractional seconds. Private provider configuration snapshots include app/version/connection/org/workspace identifiers, excluding keys/tokens. Connected live duration missing means nullable estimated cost and no fabricated zero estimated ledger; reservation remains independent. Source/inbox conversation content expires with actual worker redaction; contact identity/audit/consent/suppression history remains retained as documented in the data lifecycle runbook.
