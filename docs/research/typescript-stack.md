## Nest API and worker patterns

Use small Nest modules/controllers/application services and `NestFactory.create` for HTTP. Worker may bootstrap `NestFactory.createApplicationContext` or an explicit same-codebase TypeScript process running BullMQ workers. This is a process boundary, not a separate microservice product. Enable shutdown hooks, stop intake/intervals, await active worker completion, close queues/Redis/PostgreSQL. Signals alone do not invoke Nest shutdown hooks without `enableShutdownHooks()`; hooks run with `app.close()` or enabled SIGTERM/SIGINT listeners.

Legacy Nest decorator emission requires `experimentalDecorators`, `emitDecoratorMetadata`, and `reflect-metadata`. Compile server code with `tsc`; toolchains which merely strip TypeScript must not be assumed to emit parameter metadata. Use explicit injection tokens where appropriate. Shared contracts remain plain TypeScript without Nest decorators; browser code uses Vite bundler resolution while server builds need a coherent Node/CommonJS or ESM strategy. Root owns this configuration.

Use a custom Zod pipe or parse directly at security-sensitive request boundaries; central filter translates Zod/domain errors to a consistent error envelope. Strict objects reject unexpected command fields; provider schemas are separate and tolerate only verified vendor extensibility. Zod output schemas should validate actual read models as well as request bodies.

Readiness executes actual PostgreSQL and Redis connectivity queries. Liveness only indicates process health. Worker status distinguishes process alive, connected, and processing heartbeat; queue events are operational coordination, not product source of truth. Optional Terminus is not required to implement genuine checks.

Nest official raw-body support is `{ rawBody: true }` at factory bootstrap plus `RawBodyRequest` to access bytes. Enable only if required by a verified signature scheme. Raw bytes alone do not authenticate a webhook. Do not invent an HMAC scheme.

Nest SSE route `@Sse()` requires an RxJS Observable of `MessageEvent` (or Promise resolving one). The browser EventSource receives IDs for replay; database event IDs/cursors and authorization remain application responsibilities. A plain Express streaming response is also possible but must close polling on disconnect, emit proper headers, and bound replay batches. Never substitute in-memory queue events for persisted campaign events.

Nest official test source shows `Test.createTestingModule(...).compile()`, module service retrieval and lifecycle helpers. Contract/domain tests can run with Vitest without Nest fixtures, while integration tests should exercise authenticated real HTTP interfaces and real PostgreSQL/Redis.

## Zod to trustworthy OpenAPI

Serve an explicit OpenAPI **3.1** document with route method/path/status/security metadata and components derived from shared wire schemas using `z.toJSONSchema(schema, { target: 'draft-2020-12', io: 'input' })` for input contracts and default output conversion for responses. OpenAPI 3.1 uses JSON Schema 2020-12 semantics. Do not label draft-2020-12 schemas OpenAPI 3.0 or assume Nest Swagger decorators can infer a Zod schema.

Zod's default object parsing strips unknown properties; `z.strictObject` rejects them and always emits `additionalProperties:false`; loose objects intentionally retain extras. Keep date/time in wire contracts as strings and amounts finite JSON numbers/integers. Unrepresentable types such as `z.date`, bigint, map/set, custom values and transforms can throw on conversion. Avoid silent conversion to `{}`. Refinements and normalization rules which cannot be expressed fully in JSON Schema require documented errors and contract tests; normalization can happen after validated input rather than inside wire schema transforms. Do not use `z.fromJSONSchema`, which current docs mark experimental.

OpenAPI acceptance must compare all actual implemented methods/routes/request schemas/responses, verify security/error and binary downloads/SSE media types, and parse representative success and error bodies through the shared schemas. A static skeleton is not sufficient.

## BullMQ/Redis correctness contracts

- Producer Redis connections should fail quickly on outages (`maxRetriesPerRequest` bounded and offline queue considered) while workers should reconnect indefinitely. An explicitly supplied ioredis worker connection must have `maxRetriesPerRequest:null`; BullMQ workers use a duplicated blocking connection internally.
- Redis `maxmemory-policy noeviction` is the only documented policy guaranteeing BullMQ queue correctness. Enable persistence for local development; loss of Redis work still recovers from PostgreSQL outbox/domain state.
- `jobId` deduplicates only while a job remains stored. Removal via `removeOnComplete`, `removeOnFailed`, or manual removal permits reuse; custom IDs must not contain `:` and current docs also prohibit all-digit custom IDs. Use prefixed UUID IDs and PostgreSQL uniqueness/idempotency.
- Deduplication has simple, throttle, and debounce modes. It limits Redis job admission; it cannot guarantee exactly-once external telephone execution or replace durable inbox/outbox and conditional state transitions.
- Retry uses `attempts` total attempts, built-in fixed/exponential backoff and jitter between 0 and 1. Use bounded attempts and exponential delay with jitter for safe transient operations; permanent validation/authorization errors are terminal. Telephony ambiguity must be recorded rather than retried.
- `worker.close()` stops new jobs and waits for current processors; it has no timeout of its own. Processors must have bounded operations; Compose stop grace should allow completion. Killed processes lead to stalled recovery, which may execute a processor again and therefore requires database idempotency.
- BullMQ renews active job locks; blocked CPU/event loop can make a live job look stalled and be reprocessed. Batch imports/reports and yield; do not do unbounded synchronous work or treat a job lock as a database claim.
- `QueueScheduler` is unnecessary from BullMQ 2 onward. Do not instantiate the obsolete requirement shown in older sample fragments.
- Worker `limiter:{max,duration}` is global across workers on that queue. Group-key rate limiting was removed in BullMQ 3; don't invent tenant group limiting. DB reservations/claims enforce tenant concurrency/spend constraints. Limiter throughput and active concurrency are separate controls.
- Database remains authoritative. Outbox publication and processing are at least once; job handlers re-read current campaign/suppression/policy and skip already-completed work. A report/analysis job must never initiate a dial.

## API shutdown implementation correction

Official lifecycle source was reread on 2026-10-24 at `https://raw.githubusercontent.com/nestjs/docs.nestjs.com/master/content/fundamentals/lifecycle-events.md`: `beforeApplicationShutdown()` completes before existing connections close; `onApplicationShutdown()` executes after connections close. An actual composed API restart while SSE remained open took 30,435ms and Docker emitted exit code137, demonstrating that resource cleanup after adapter close cannot release an active stream. The implemented `StreamsService` closes registered HTTP responses and stops polling in `BeforeApplicationShutdown`; Pool/Redis cleanup remains after adapter close. No undocumented force-close option is used. Final restart-test evidence is recorded in the API runbook/root verification after rebuilding the changed image. Docker event flags were checked against installed official `docker events --help`; the test captures live die events because post-hoc daemon history was empty in this environment.

Final rebuilt Compose verification: the same active-SSE restart completed in 358ms with a captured Docker die exit code143 (normal SIGTERM) and preserved four unique terminal mock outcomes plus cursor replay. `npm run test:integration` passed 28 tests in five files, 83.39 seconds. The dedicated API restart test also passed individually. This replaces the forced-kill behavior measured above; no force-close flag or real provider call was used.
