## Recommended open monochrome layout

A compact left navigation provides workspace identity, primary operations and a small management group. Keep all existing routes discoverable: Overview, Campaigns, Contacts, Agents, Live Activity, Reports, Integrations, Settings and Audit. Workspace identity is meaningful text; a workspace switcher must only look interactive if switching actually works. Use a single active-route treatment and small consistent icons. The header carries page title, short context, mode and one primary action.

Use white main canvas, near-black primary text, restrained neutral secondary text, subtle gray separators and black primary actions. Apply actual shadcn semantic tokens in Tailwind, including focus, input, popover and sidebar tokens. Reserve elevated boxed surfaces for dialogs/popovers and functional upload targets. Normal page sections are open and separated by spacing or one horizontal rule. Recommended working dimensions, as design decisions rather than vendor promises: approximately220–240px desktop navigation,24–32px content gutters,28–32px page headings,14px main labels/body,13px secondary metadata,40–48px table rows, and4–6px control radius. Small screens use16px gutters and a named navigation Sheet.

| Surface                       | Concrete composition                                                                                                                                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview                      | Title/action row, one open row of real counts separated by thin rules, recent campaign table, persisted activity list and a useful first-run action. Each count shows units and separates live from simulation.                       |
| Campaigns                     | Heading/action, one filter toolbar, full-width table with campaign name/objective preview, mode, lifecycle state, real terminal/total progress and row actions. Avoid giving each campaign its own boxed tile.                        |
| Campaign wizard               | Compact step indicator, focused labeled form and a clear review area. Five-persona selection can be a radio list. Policy/currency units remain explicit. Save/plan never triggers execution; confirmation is a separate named Dialog. |
| Contacts/imports              | Upload/mapping controls, import status and an open validation table. Row issues/corrections remain tied to source indices. Distinguish excluded duplicates/suppression from blocking invalid rows.                                    |
| Agents                        | Five editable row/list entries with name, description, immutable version and Edit/Sandbox actions. Configuration lives in a dialog or focused detail surface. No duplicated visual/code paths per persona.                            |
| Live Activity/campaign detail | Real outcome summary strip, chronological persisted event rows and a contact outcome table. Connection/replay status is visible. Refresh/reconnect recovers database truth; no decorative progress timer.                             |
| Call inspector                | Compact identity/outcome header, attempt history, structured answers and authorized transcript sections. Unknown values stay unknown. Synthetic content is marked explicitly.                                                         |
| Reports                       | Job/status/format/row-count table, safe download actions and genuine pending/failure/expiry states. Display the report's execution mode, not an inferred global default.                                                              |
| Integrations/settings/audit   | Open key/value sections and chronological audit rows. Display readiness/capabilities without secret values or provider-specific configuration identifiers.                                                                            |

`SIMULATION`, `SIMULATION DEFAULT` and `LIVE` remain unmistakable text labels. A light neutral outlined simulation badge and a high-contrast black live badge provide distinction through both text and treatment. Connection/outcome states also retain visible words; monochrome cannot make color the sole state signal. Live review continues to disclose provider readiness, eligible/excluded contacts, policy, cap and cost assumptions, while sending no launch command until explicit confirmation.

The no-external-request browser assertion must remain. Use locally available/self-hosted typefaces and assets; reference sites are research sources, not runtime CDNs. Do not copy their logos, marketing illustrations, fake metrics or domain vocabulary into this product.

## Browser acceptance contract for real shadcn primitives

The current browser suite covers full persisted CSV correction → immutable persona version selection → local plan → explicit simulation → SSE refresh/replay → call analysis → CSV/XLSX download, development identity, mobile overflow/reduced motion, keyboard dialogs and explicit XLSX mapping. Preserve these assertions and all no-auto-launch/no-live-request checks through the redesign.

The native DOM-tag assumption `document.querySelector('dialog')` must change once Radix content uses a portal and a `div[role=dialog]`. Prefer Playwright `getByRole('dialog')` and evaluate focus containment on that locator. The assertion should verify behavior, not the component's HTML tag. Keep accessible title, Tab/Shift+Tab containment, Escape dismissal and return focus to the real opener. A controlled Radix Dialog rendered without a DialogTrigger needs explicit opener restoration; the UI owner is handling `onCloseAutoFocus` against a captured opener.

The mobile Sheet should have accessible name `Navigation`, opener `Open navigation`, close `Close navigation`, and close upon route selection. Scope mobile links to the sheet dialog while it is open to avoid matching a desktop navigation copy. Preserve the nonoverflow assertion at390px width; table scrolling is contained within its own surface.

The UI owner selected NativeSelect for mapping/wizard fields, preserving meaningful HTML `selectOption` acceptance. Radix Select filters should be tested through the actual named combobox and option roles. Existing visible form labels and launch actions remain the primary selectors. Root coordinates image rebuilds; browser execution waits for the rebuilt current UI and healthy Compose services.
